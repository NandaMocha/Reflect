## ▶ IMMEDIATE NEXT ACTION: H4, but clean the Dev schema first

**Production CloudKit schema is effectively append-only — record types and fields cannot be removed
once deployed.** Production has never been deployed for this container, so this is the one chance
at a clean schema.

**Confirmed present in Development and needing deletion first** (checked 2026-08-05):

- `Response` record type — superseded by `Answer`
- `promptText` field on `SpaceReflection` — superseded by `questionsJSON`

Both are verified dead in code: zero Swift references to `promptText`/`responseText` (the only hit
is a comment at `Reflect/Data/Space/SpaceStore.swift:43`), no `"Response"` record-type string
anywhere, and `SpaceRecordType` declares only `Space`, `SpaceReflection`, `MemberProfile`, `Answer`.
This is leftover from TASK-006's manual CloudKit reset, which was never completed.

Leaving them in would not break anything — they would be unused clutter, not a bug — but they would
be permanent, and a stray `Response` type will mislead whoever does the next schema change.

### Deletion steps (CloudKit Console, **Development**)

1. Data → Records → query type `Response` → delete any records (a type with live records usually
   will not delete)
2. Schema → Record Types → `Response` → Delete
3. Schema → Record Types → `SpaceReflection` → remove field `promptText` (and `responseText` if
   present)

If the Console version does not offer field deletion, the fallback is **Deployment → Reset
Development Environment**, which wipes Dev schema *and* data. That works but costs: re-creating
`PendingClipFeedback` plus its two Queryable indexes by hand, re-running the app to regenerate the
Space types, and rebuilding test data. Try targeted deletion first.

## App Clip — decided design

Full plan: [app-clip-plan.md](app-clip-plan.md). Estimate ~14.5–19.5 working days of Clip work.

### The flow (decided 2026-08-05)

1. Link opens the Clip directly on **"Your Feedback"** — one request's composer, *not* a Space
   reflection list
2. **A name alert on first open** becomes the guest's identity; persists so a re-open does not re-ask
3. Guest answers the request's 1–5 questions and submits
4. **Then "All feedback"** — every member's answers, matching the app's write-yours-before-you-see-
   others gate

Mirrors the app's `Presentation/Features/Space/Thread/SpaceThreadView.swift` and
`Thread/SpaceAllResponsesView.swift` (row: `Thread/AnswerBubble.swift`). The Clip reimplements these
against a Clip-local repository — it must **not** import them, as they drag in `DIContainer` and
SwiftData.

### Three consequences that reshape the plan

- **The link is per-request, not per-Space.** The token resolves to a single `SpaceReflection`, so
  it is minted when a specific feedback request is shared. Reshapes tasks 2.1 and 2.3.
- **Guest identity must be synthesized.** The app keys authorship on `memberRecordName` via
  `MemberProfile`; a Clip guest has no CloudKit user record. Use a keychain UUID `guestId` + the
  name from the alert (task 2.7).
- **An optimistic local echo is mandatory.** A guest's answer only reaches the public mirror after
  the *owner's* app next syncs and re-posts it — potentially days. Without a local echo, the guest
  is sent from composing straight to a feedback page missing what they just wrote. Tasks 3.2/3.3.

### Hard platform constraint

**App Clips cannot write to CloudKit at all** — not private, shared, or public. Re-verified
2026-08-05 and unchanged; Apple states it is deliberate ("when an App Clip isn't used anymore, iOS
will delete the App Clip and its data"). This is why a server-side write endpoint is mandatory and
why read-only is not a viable descope given the flow is centred on posting.

### Open decision

**Guest feedback: auto-posted, or held for owner approval?** Changes task 2.6's design and matters
for App Review UGC guideline 1.2, since unauthenticated guests posting content is the feature's
whole point. Owner approval gives a real moderation choke point. **Not yet decided.**

### AASA — deployed and serving

Live at `https://nandamochammad.xyz/.well-known/apple-app-site-association` — verified 200,
`content-type: application/json`, **0 redirects**, body identical to
[`../../scripts/appclip-aasa.json`](../../scripts/appclip-aasa.json).

- Filename has **no extension**. Because LiteSpeed types by extension and sends `nosniff`, a
  `.well-known/.htaccess` containing `ForceType application/json` is **required**, not optional.
- `www` → apex 301, and Apple's fetcher does **not** follow redirects, so the **apex**
  (`nandamochammad.xyz`) is what belongs in the `appclips:` entitlement.
- Let's Encrypt cert SAN covers the apex explicitly — the wildcard CN alone would not have.
- Registers `/f/*` for the full app (`9NAU7R3577.xyz.nandamochammad.Reflect`) and the Clip App ID
  (`9NAU7R3577.xyz.nandamochammad.Reflect.Clip`).
- **Not functional yet** — the Clip App ID does not exist in the portal. iOS also CDN-caches AASA;
  use Settings ▸ Developer ▸ *Associated Domains Development* when testing on device.

### CloudKit write path — PROVEN end to end

[`../../scripts/appclip-cloudkit-write-test.php`](../../scripts/appclip-cloudkit-write-test.php) ran
green from the live host: signed request accepted, `PendingClipFeedback` created in the **public**
database, deleted again (both HTTP 200). Task 2.5 is ordinary engineering from here.

**Signing scheme** (reusable directly in the real endpoint — see `cloudkit_request()` in that script):

```
message   = "<ISO8601 date>:<base64(sha256(body))>:<subpath>"
signature = ECDSA/SHA-256 over message, base64-encoded
headers   = X-Apple-CloudKit-Request-KeyID
            X-Apple-CloudKit-Request-ISO8601Date
            X-Apple-CloudKit-Request-SignatureV1
endpoint  = POST https://api.apple-cloudkit.com/database/1/<container>/<environment>/public/records/modify
```

**Gotchas learned the hard way:**

- **Server-to-server keys CANNOT create schema.** Unlike a first write from the app, nothing
  auto-creates. Every public record type must be defined in CloudKit Console by hand first. This
  applies to `MirroredRequest`/`MirroredAnswer`/`TokenIndex` in task 2.2 too — budget for it.
- **The Key ID is not the public key.** The Key ID is 64 hex characters, returned by the Console
  *after* you paste the public key in. Pasting the public key instead yields a bare
  `AUTHENTICATION_FAILED` that points at nothing. The script now guards against this.
- A `403` on a file that other names return `404` for means the file **exists** and permissions are
  blocking it — that is how the private key was found sitting in the web root.

### `PendingClipFeedback` — exists in Development

String fields: `requestToken` (**Queryable**), `questionId`, `guestId`, `guestName`, `body`.
Plus a **Queryable index on `recordName`** — without it CloudKit throws "not marked queryable" on
`CKQuery`, a known trap in this project.
